# 5.0.0 历史读取与上下文续聊

## 大历史传输修复

桌面旧管道把每个历史 snapshot 作为一个 JSON 物理帧发送。超过 512 KiB 时发送失败，切换会话或重启后的历史重载因此可能出现 `runtime carrier Error`。此错误不能证明会话文件损坏，也不能证明官方内核不支持旧格式。

桌面管道协议版本 3 对较大的逻辑流消息按 192 KiB UTF-8 字节分块，无损重组后再交给官方运行时与渲染桥。512 KiB 物理帧限制仍保留；单个逻辑 JSON 消息限制为 32 MiB，保留 16 MiB WebSocket 载荷经 base64 编码后的空间。HTTP body 的独立累计限制仍为 320 MiB。

接收端在身份握手成功后才启用分块；校验总长度、片数、顺序、base64、SHA-256 与最终消息类型。缺片、截断、错误和取消不得返回部分历史。接收队列采用高水位背压与硬预算；传输诊断只包含固定错误码、关联 ID、白名单操作及字节预算，不记录用户内容或凭据。新旧管道版本混用会在握手时拒绝。

本修复只修改桌面自有代码，不改官方 DSH 源码、NPM 包或用户会话文件。安装更新后先尝试重新打开原会话；不要删除会话库或重置 profile 来处理此类错误。

## 可选摘要续聊

在扩展坞的对话导入页展开旧 DSH 会话上下文摘要引导，可复制提示词。优先更新并重新打开原会话，摘要不是历史修复的前置要求，也不是无损迁移。

用户自行备份和审阅 JSON / JSONL，移除凭据与隐私，仅向自己信任的供应商手动发送必要内容，并确认费用。压缩存储文件不可直接当作文本上传。入口不自动读取、上传或调用模型；摘要只能保留可识别的目标、事实、决策和待办，不能恢复原附件或工具运行状态。

## 验收边界

使用合成数据和本地免费模型验证大历史首次生成、A→B→A、重启加载及字节完整性；格式迁移使用隔离夹具。用户现场报告的会话数量和测量值不作为本机通过结果。正式 Setup 新装、覆盖升级与回滚仍需要干净 Windows 环境；仅提取安装包启动不等于正式安装验收。
