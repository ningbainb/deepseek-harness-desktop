# Desktop 4.2.0 upstream Web sync ledger

This ledger records the source of truth for the 4.2.0 Web plugin migration. It is not a completion claim. The inspected upstream is [`zhu1090093659/dsh-web`](https://github.com/zhu1090093659/dsh-web), branch `alpha`, commit [`29fd16ae968fb617323be179915f480b289a3886`](https://github.com/zhu1090093659/dsh-web/commit/29fd16ae968fb617323be179915f480b289a3886). Its package manifests say `0.3.23` and require DSH `>=0.1.6-alpha.2`.

The published `@linxin666/dsh-web-all@0.3.23` tarball is **not** this source snapshot: its DSH floor is `>=0.1.5-rc.1` and its aggregate patch includes `dsh-better-sidebar`, which the alpha source excludes. The tarball and source patch hashes are recorded in [the investigation](archive/desktop-4.2-upgrade-investigation.md). A registry version match is not enough to promote the aggregate. The alpha-source cohort is pinned in `vendor/dsh-web-alpha-0.3.23/provenance.json`; `node scripts/verify-upstream-web-cohort.mjs` verifies all 21 packages, the commit, patch digest, and every advertised package entrypoint. The initial source packs omitted compiled files from several packages; those were built from the pinned source and repacked. The source `dsh-i18n` manifest advertises an `./invariant` export with no corresponding source or output, so only that invalid export was omitted from its vendored manifest. The isolated 4.2 candidate now mounts this aggregate in place of the 4.1 carrier. This is **not a release acceptance claim**: complete interactive smoke gates remain pending.

The 4.1 aggregate and the alpha aggregate both insert `web-ui-compat`, `web-ui-settings`, `web-ui-plugin-manager`, `web-ui-task-board`, `web-ui-git-graph`, `web-ui-remote-web-ui`, `web-ui-pet`, `web-ui-ssh`, `web-ui-describe-image`, `web-ui-liangshen`, `web-ui-skill-explorer`, and `web-ui-skin-center`. Mounting both aggregates would collide. The old aggregate also inserts nine Desktop-owned rows missing from the alpha aggregate: `user-scope`, `ui-model-preferences`, `personal-prompt`, `memory`, `web-ui-mode-switcher`, `live-stats`, `web-ui-dsh-aionui-panel`, `web-ui-chat-recovery`, and `web-ui-desktop-launcher`. A switch must retain these rows, their saved disable overrides, and their direct package sources. The alpha Skin Center tarball currently includes one skin directory (`blue-fantasy`), whereas the Desktop 4.1 catalog has 15 IDs; replacing the Desktop carrier without a skin-preserving overlay would regress existing choices.

Before changing a row to synced, record the exact upstream commit, local patch diff, package build and mount tests, saved-state round trip, and whether an existing Desktop entry remains reachable. The Desktop profile, not the root `package.json` alone, determines the actual mounted plugin graph.

The first full-profile browser boot exposed an alpha.2 list-slot contract change: the patched 4.1 Chat Recovery bundle registered `conversation.chat.turnTail` without an ID, which caused the entire Web boot to display "Failed to load plugins". The Desktop package patch now assigns `chat-recovery-turn-actions`; the complete profile Runtime integration test passes again, including the 15-skin catalog and pet endpoints. The model-capabilities 0.3.20 Desktop Dock patch is still selected directly because alpha 0.3.23 does not contain its `data-dock-dirty` and `data-dock-save` hooks. The new aggregate rows for Model Capabilities, Usage, and Session Archive stay disabled while their existing direct Desktop bundles remain mounted, preventing duplicate host registrations before a saved-state migration is reviewed.

The alpha aggregate marks SSH, Describe Image, and Liangshen opt-in, while the 4.1 Desktop aggregate mounted all three. Desktop keeps Describe Image and Liangshen on their alpha rows. SSH instead uses the retained Desktop `ssh` row because the upstream five-tab client does not preserve the Desktop six-tab workflow; `mergeDesktopPatch()` maps old `web-ui-ssh` user rows to `ssh` so enabled state and config follow the preserved client. The packaged SSH regression passed GUI host creation, password-auth connection, PTY input/output, host reuse after a full application relaunch, and the single-window invariant. A real Runtime regression mounts a 4.1 Liangshen preset, verifies the upstream `tool-catalog` replaces the removed `tool-bootstrap`, and creates a session without changing an existing Session marker.
