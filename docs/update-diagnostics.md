# 更新失败诊断

## 先诊断现有失败

让遇到失败的用户打开应用的日志文件夹，保留失败前后同一次操作的 `runtime.log`；日志已轮转时同时保留对应旧文件。记录当前版本、计划升级版本、发生时间，以及自动更新还是手动运行安装包。优先使用应用已有的诊断导出功能脱敏，不要把未审阅的日志直接公开。

在仓库中可先对单个日志执行本地只读分析：

```powershell
node apps/dsh-desktop/scripts/diagnose-update-log.mjs 'D:\support\runtime.log' 'D:\support\update-report.json'
```

输入最多 16 MiB；报告只含阶段、固定错误分类、版本和日志行号，不包含错误原文、路径或密钥。报告文件必须不存在，避免覆盖原始材料。旧日志阶段是根据相邻行推断的，无法分类时保持未知。

| 日志/阶段 | 首先检查 |
| --- | --- |
| `checking from` 后出现网络错误 | 检查更新元数据的连接、DNS、代理、HTTP 状态；此时还未开始安装 |
| `is available` 后下载失败 | 安装包下载线路、连接中断、磁盘空间 |
| 校验失败 | SHA 校验、签名和发布元数据是否与同一安装包匹配 |
| `prepare` | 旧 Runtime 退出、扩展操作结束及安装前准备是否超时 |
| `install` | 安装器启动权限和启动超时；不代表安装器内部全部步骤已被观测 |
| 下载完成后出现迁移阻塞 | 查看启动诊断、安装事务及迁移状态，避免误判为下载失败 |

对一名用户的一次操作，按时间串起检查、下载、校验、安装准备、启动安装器和再次启动。只出现下载完成，不能证明安装完成；没有再次启动回执，也不能自动判定失败。用户直接双击安装包的过程，需要另取安装事务记录和失败界面信息。

支持 v3 安装事务的版本会在 `%TEMP%\dsh-desktop-installer-transaction-*\transaction.json` 保存事务状态；成功清理后可能不存在。取证时只读取，不运行 Begin、Commit、Rollback 或 Cleanup，也不要删除事务目录。事务文件可能包含安装路径，分享前需要脱敏。

## 新版本自动诊断

继续使用原有 `update_*` 事件名称，schema 6 增加 `update` 参数：尝试 ID、阶段、固定错误类别/代码、源版本、目标版本、线路类别、线路尝试序号、更新通道和发生时间。检查阶段尚不知道目标版本时使用 `unknown`。

同一次检查及其下载备用线路使用相同尝试 ID；下一次检查是新尝试。安装前回执把原尝试 ID 保留到目标版本启动。`update_completed` 表示目标 Desktop 已启动，不代表主 Runtime 或项目已健康运行。

失败优先上报，在原有 `analytics_failure` 行内保存诊断 JSON；按尝试 ID 与阶段幂等写入，无新增明细行或二级索引。成功阶段进入 Analytics Engine，本地结构化日志使用 `[update-diagnostic]` 前缀，下载进度不会逐次写结构化日志。统计发送、日志写入及 D1/AE 故障不能改变更新结果。安装准备只限时发送待上报数据，保留安装器启动失败的上报能力。

AE 第 17 个 blob 保存更新诊断，不改变既有汇总的分组维度；字段和批大小受严格限制，并核对了 Cloudflare 的每点最多 20 个 blob、合计 16 KiB 限制。[官方限制](https://developers.cloudflare.com/analytics/analytics-engine/limits/)

管理看板增加“更新失败诊断”，支持当前运行版本筛选、阶段与错误分类分布、失败尝试数、观测到的去重安装实例及最近 50 条失败。受失败保留期限制，最多查看最近 30 天。接口为登录后的 `/admin/api/update-diagnostics?days=7&version=3.4.0`，版本参数可为空。失败实例只覆盖具备诊断字段的客户端，不能用其推算全部用户安装失败率。

## 部署和验收

先部署 Worker 迁移 `0006`、`0007` 与 schema 6 接收端，再分发支持诊断的新桌面版本。AE 绑定和 `ANALYTICS_READ_TOKEN` 是原有汇总部署的前置条件；本次本地实现不会自动修改生产配置。旧版历史错误无法补出当时未记录的错误码。

对网络中断、HTTP 错误、校验失败、权限拒绝、磁盘满、退出超时分别注入故障，验证阶段和错误分类；确认重试不重复写同一失败行、日志/上报异常不影响流程。另在隔离的 Windows 环境中执行受支持旧版本到候选版本的实际覆盖升级，包含应用运行中、自定义安装目录和升级后再次启动；普通桌面回归不能代替安装器升级验证。
