# Desktop 5.2.0 Empty Directory Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task by task. Preserve the existing dirty worktree and validated candidate.

**Goal:** Reduce Windows installation metadata work by omitting only empty directories belonging to material already excluded from the runtime package.

**Architecture:** Extend the existing packaging pruner, using its existing file classification rules to recognize eligible directory paths. Traverse without following links and remove eligible empty directories with atomic, nonrecursive `rmdir`; preserve every file, unknown directory and non-Windows payload. This refines the existing performance plan's installation-write optimization and adds no product feature or runtime dependency.

**Tech Stack:** Node filesystem promises, existing CommonJS afterPack hook, Node test runner, Windows NSIS/7z packaging.

**Spec:** [Existing performance plan](2026-10-27-desktop-5.2.0-performance-plan.md); experiment evidence under `E:/DeepSeekHarnessDesktop-Build/artifacts/desktop-5.2.0-performance-20261027/empty-directory-experiment/`.

## Review Focus

- Unknown empty directories, including compatibility and type-location stubs, remain present.
- An eligible directory containing any file, license or runtime asset remains untouched by the directory helper.
- A junction/symlink at the root, a descendant or any ancestor prevents writes through that link.
- Files appearing immediately before removal survive; ENOTEMPTY/EEXIST has no recursive fallback.
- Non-Windows targets preserve existing trees and repeated cleanup is idempotent.
