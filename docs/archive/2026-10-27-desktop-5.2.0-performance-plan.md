# Desktop 5.2.0 安装包与性能优化计划

目标：在保留插件、皮肤、入口、用户资料、安装事务回滚与安全校验的前提下，减小包体、减少安装写入与启动开销。授权来自用户本轮“优化安装包大小、安装速度和整体性能”的明确请求。默认在当前 E 盘工作树连续实施，不发布，不改变原资料。

## 已验证基准

- 旧 Setup：449014878 字节；新计算哈希与备份记录在 `artifacts/desktop-5.2.0-performance-20261027/baseline/artifact.json`。
- 实际安装树：1580019908 字节，26233 文件。ASAR 头中的历史清单包括打包后已清理的文件，不能代替物理清点。
- 嵌套 Electron：383668289 字节；浏览器依赖需要 bare Electron 能力，不能直接删整个运行时。
- 嵌套 locales：55 文件、50644046 字节；桌面现有 `electronLanguages` 仅声明 en-US、zh-CN、zh-TW，三者合计 1762574 字节。对齐这份现有配置可少写约 48.9 MB，其压缩后收益待实测。
- 当前 7z 普通配置已经传入 `-mx=9`；改成 maximum 不产生 7z 压缩级别提升。

## 实施顺序

1. 保留旧 Setup，记录当前源码状态和 lock；测隔离资料启动与重复启动。新资料启动不等于清空操作系统缓存的冷启动。
2. 新增打包阶段的嵌套 Electron 语言一致化：只作用 Windows 产物、只按有效的现有显式语言清单清理。所有支持语言和 en-US 回退必须存在；无配置、未知配置、缺失语言、链接路径保持原文件。主程序、browser、DLL、图标、许可证不变。先用真实文件夹夹具复现缺失行为，再实现并保留所有现有断言。
3. 根据独立启动链路审查定位重复 I/O；以当前源码的同机实测选择实现，保留身份校验、故障恢复、模型/会话持久化与变更检测。不以禁用功能或静默缓存陈旧状态获得速度。
   当前选定：同一次 `ensureDesktopProfile` 内共用父目录创建 Promise，后续调用重新建立；原有逐包路径/身份/所有权检查不变。全身桌宠空闲 tick 仅在状态文字或动作标记变化时写 DOM，保留原 RAF 调度、任务联动及交互。可见文档的 60 帧用例先复现 60 次重复状态写入，修复后为 0 次，真实动作变化下一帧仍更新。
4. 比较产物字节数、解压写入耗时和隔离启动指标；排除仅把安装耗时转移到首启的方案。若更深入的压缩实验不能改善实测，保留原压缩设置。
5. 构建本地未签名包，运行包身份、ASAR、功能基线、源码与成品回归、隔离升级/重启及真实浏览器验证。记录真实 Setup 大小与 SHA-256；不把中间文件当成安装包。
