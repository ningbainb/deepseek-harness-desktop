# Desktop 5.2.0 桌宠默认与提案审查

本次明确需求：官方皮肤继续作为界面默认皮肤；新用户默认显示全身桌宠并开启预测下一句，保留已保存的关闭选择。全身桌宠显示期间，原桌宠暂停挂件和客户端轮询，避免同时出现两个桌宠。关闭全身桌宠后，原桌宠按原启用设置恢复；不修改原选择、位置、尺寸或数据，原设置入口保留。

实现采用官方 NPM SDK、既有 profile/Cordis 组合及社区包中央补丁。没有修改官方源码、官方 NPM 包或直接写入 node_modules。社区原始 tgz 保留原字节。新版适配器发送文档显示策略；原桌宠复用既有资源清理与重新挂载路径，保留设置窗口的提前返回和终态防护。

证据目录：`E:/DeepSeekHarnessDesktop-Build/artifacts/desktop-5.2.0-defaults-20261027/`。此前安装包的验收快照见 [2026-10-26 本地验收记录](2026-10-26-desktop-5.2.0-local-validation.md)，该安装包未包含本次默认值及显示优先级变更。

## 验证范围

- 默认皮肤保留；没有保存选择时只创建一个全身桌宠。
- 原桌宠显示和客户端轮询停止；关/开全身桌宠可恢复/卸载原挂件，原配置读回保持一致。
- 晚到读取不能恢复已卸载挂件；卸载适配器、热更新和最终销毁的监听及资源清理。
- 原生插件设置、预测的默认开启及明确关闭、跨会话晚到建议隔离、跨窗口草稿与模型预算保持。
- 普通鼠标发送、Tab 只接受草稿、实际可见浏览器和退出清理。
- 旧桌宠专项明确建立新版关闭的隔离前提，保留原断言，结束恢复原存储状态；默认新版场景由独立原生用例验证。

## 已保留的失败证据

首次默认值原生验收在 `prompt-session-isolation` 阶段失败：旧桌宠的气泡/菜单截获普通发送按钮鼠标点击。官方默认皮肤和两个新用户默认值已进入验证，但该整轮失败，不能算通过。没有使用强制点击、键盘替代或隐藏断言。后续按用户明确要求实现单桌宠显示优先级，再进行新整轮验证。
