# macOS Desktop 3.5 开发与验证记录

验证日期：2026-09-13。基线：`origin/main@5696033`，工作分支：`codex/macos-3.5-validation`。设备：Apple Silicon，macOS 27.0（26A428），Node 24.18.0，pnpm 11.22.0，Electron 43.4.0，官方 NPM DSH 0.1.5-rc.1。

## 当前结论

本地完整桌面回归已在同一轮执行 29 个调度单元，其中 28 个通过，拓展坞原生最小化失败。完整门禁仍以非零状态结束，不能宣称全绿或已满足发布门槛。macOS 15 的核心回归已在 [Desktop CI 34765798498](https://github.com/ningbainb/deepseek-harness-desktop/actions/runs/34765798498) 通过，包括原生最小化；该轮后续全仓测试及 Windows DPI 验收仍失败。本文记录此检查点，后续 CI 结果见 [PR #81](https://github.com/ningbainb/deepseek-harness-desktop/pull/81)。

最终整轮机器可读结果是 28 通过、1 失败。工作区移动测试会在重启前确认准备数据落盘；终端测试使用隔离的 shell 配置，避免本机 zsh 初始化覆盖候选包的 pnpm 路径。拓展坞套件继续执行了最大化、还原和关闭检查，只有最小化断言失败。

## 实现

- [退出流程](../../apps/dsh-desktop/src/electron-app.mjs)在停止 Runtime 前检查设置草稿，支持返回编辑、保存后退出及失败后重试，避免 macOS 原生退出被异步窗口关闭取消。
- [窗口标题栏](../../apps/dsh-desktop/src/window-chrome.mjs)使用侧边栏既有标题栏兼容机制避让右侧按钮，保留手动兼容高度；mac 菜单和内置终端显示 Command/Option 快捷键，并补齐原生 Window 菜单。
- 终端 PATH 分隔符、Windows 进程树路径和崩溃码格式化使用显式目标平台。修复依赖子包的旧 pnpm 声明，安装可通过 Corepack 正常完成。
- 完整回归要求显式指定 mac `.app`，拒绝误用旧 `dist`；SSH、bash Agent 工具、图片拖放与内存采样具备 mac 路径。`--keep-going` 保留失败状态并执行余下套件，没有降低已有行为断言。
- 回归清单使用稳定 ID，记录 source、fixture 或 packaged 测试对象；执行器生成原子 JSON 报告、逐项日志、套件和清理期限，并绑定测试摘要及候选可执行文件、`app.asar`、`Info.plist` 摘要。
- 设置窗口和代理路由在 packaged 模式启动明确指定的候选包；安装包启动矩阵缺少候选时直接失败，不再以成功退出码报告 `SKIP`。
- [mac 生命周期验收](../../apps/dsh-desktop/scripts/verify-macos-lifecycle.mjs)覆盖未签名更新限制、原生菜单、关闭隐藏、Dock 唤回、草稿取消退出、保存后退出和子进程回收。
- CI 增加 `macos-15` ARM job、mac 打包校验、隔离启动及生命周期检查。最低系统声明对齐所捆绑 Electron 的 `LSMinimumSystemVersion=12.0`。详见[构建指南](../macos-preview.zh.md)。

## 原生最小化复现与待验证项

[独立复现脚本](../../apps/dsh-desktop/test/fixtures/macos-native-minimize.cjs)不加载任何 Desktop 代码或 DSH 插件，使用标准 Electron BrowserWindow，并把数据放在临时目录。在本机调用 `minimize()` 后 `isMinimized()` 仍为 `false`，退出码为 1；额外用本机 Electron 44.0.0 的空白窗口也观察到相同结果。通过 LaunchServices 启动候选包后，真实点击黄色最小化按钮仍无效；移除窗口父子关系的对照也无效并已撤回。该现象在 macOS 27.0 上同时影响空白 Electron 与应用窗口，macOS 15 CI 对照中的原生最小化已通过。

```bash
pnpm --filter @deepseek-ai/dsh-desktop exec electron test/fixtures/macos-native-minimize.cjs
```

macOS 15 核心回归通过后，全仓测试暴露设置页测试夹具没有清理 effect 返回的定时器，Windows 则暴露最大化还原对逻辑坐标的覆盖和虚拟拓扑与物理屏幕尺寸的差异。修复包含还原状态保护、effect 资源清理及按实际屏幕工作区精确校验原生尺寸；本地完整 verify 已通过，需等待新一轮远端 CI 完成打包与生命周期步骤。macOS 27 的最小化失败没有设为允许失败，也没有删除入口或跳过断言。

自动化 E2E 均使用独立 `DSH_HOME` 与 user-data。手工 computer-use 阶段，测试进程退出后曾自动拉起默认 Desktop 实例；已关闭，但默认 `~/.dsh/profiles/desktop` 的生成配置在 20:19 被该次启动更新。没有回滚或删除真实用户数据；最终隔离冒烟另外验证了其测试期间真实 `~/.dsh` 快照不变。
