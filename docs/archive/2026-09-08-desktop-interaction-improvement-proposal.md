## 2. 性价比模式：统一中文和使用入口

预设的 `description` 确实是英文，名称也以 `Value Mode` 开头；客户端另有中文词条，但设置卡片存在独立硬编码文案。这说明预设元数据与界面文案没有统一。英文预设是当前发现的直接候选来源，最终需用用户所见入口核对。

“性价比模式”作为统一功能名；拓展坞可显示为“模型协作”，并在页内标明“性价比模式”，让用户知道两个入口指向同一项配置。型号、供应商名称和 API 标识保持原名，中文界面不在每个标题后重复英文。

## 3. 拓展坞拖动：先分清窗口，再优化绘制

### 当前证据

拓展坞是独立桌面窗口，其设置内容包含嵌入视图。另一个主界面设置弹窗具有自定义拖动逻辑，当前每次指针移动都会计算布局并更新位置、尺寸和多个缩放手柄。该路径存在优化空间，但不能据此直接断定独立拓展坞的卡顿也由同一个原因造成。

代码依据：[窗口创建](../../apps/dsh-desktop/src/window-factory.mjs)、[拓展坞设置视图](../../apps/dsh-desktop/src/dock-settings-view.mjs)、[设置弹窗拖动](../../apps/dsh-desktop/src/settings-window.mjs)。设置弹窗当前已经在松手后保存位置，应保留这一行为。

### 拟定行为

- 独立拓展坞通过标题栏空白处拖动；关闭按钮、搜索框和其他控件保持可点击，不被划入拖动区域。
- 内部设置弹窗通过标题区域拖动，正文区域继续用于选择文字和滚动。
- 拖动跟随指针，不加缓动或位置过渡；松手不回弹、不偏移。
- 新建项目弹窗默认居中，以完成表单为主，不额外加入拖动手柄。
- 保留已有居中打开与位置记忆规则；窗口越过屏幕边界时确保标题栏仍可找回。

### 优化路径

| 场景 | 实施方向 |
| --- | --- |
| 独立窗口拖动 | 优先使用系统原生标题栏拖动；检查嵌入视图是否重复布局、主题同步或整页重绘 |
| 内部弹窗拖动 | 合并同一帧内的指针更新；拖动期间通过位移绘制，松手再提交最终布局坐标 |
| 弹窗缩放 | 每帧最多更新一次尺寸，避免交替读取与写入布局；结束后保存 |
| 特效参与卡顿 | 仅在确认相关后，拖动期间降低粒子、模糊或重阴影的开销，结束后恢复 |
| 手势中断 | 失焦、取消、松手或窗口关闭均清理监听和临时状态 |

测量方案：在同一测试机、同一分辨率和刷新率下，各录制三轮 10 秒拖动，覆盖拓展坞普通页、嵌入设置页、内部设置弹窗，以及主界面正在输出内容的场景。记录配置、帧间隔、超过 50 毫秒的长任务和松手位置。

拟定目标：60 Hz 测试环境中，渲染拖动的第 95 百分位帧间隔不超过 20 毫秒；拖动路径不引入超过 50 毫秒的持续阻塞；松手后 100 毫秒内完成位置收敛。窗口原生移动另结合系统画面与合成情况检查，不能仅用页面帧率宣称整窗流畅。硬件不满足目标时报告实测结果，不把目标写成已达成。

## 4. 内置浏览器：明确关闭位置和关闭结果

用户反馈缺少关闭按钮，但本轮尚未确认具体浏览器承载组件，以及按钮是未提供还是被窗口层遮挡。实施前需复现打开路径，确认是应用内页面、侧栏还是独立窗口，再接到对应的关闭生命周期。

### 交互设计

- 浏览器容器右上角固定显示 `×`，悬停提示“关闭浏览器”，可用键盘聚焦；点击区域至少 32 × 32 像素。
- 按钮属于应用容器，不依赖网页自身加载。加载中、网络错误和页面滚动时始终可见。
- 如果已有多个网页标签，每个标签有“关闭标签页”；容器右上角用于关闭整个浏览器面板，二者文案和层级区分清楚。
- 焦点在浏览器内时，`Ctrl+W` 关闭当前标签；没有标签体系时关闭当前浏览器容器。关闭最后一个标签后收起浏览器，恢复对话区域。
- 关闭后焦点回到打开浏览器的入口；入口已不存在时回到对话输入框。
- `Esc` 优先退出网页弹层、菜单或全屏，不将其全局绑定为关闭浏览器，减少误关。
- 关闭保留当前对话、草稿和登录状态；释放该浏览器实例的页面资源及监听。网页确有未提交表单时沿用已有离开提示，普通浏览不增加确认弹窗。

视觉上复用现有标题栏按钮，避开系统窗口控制区。验收必须包括深浅主题、窄窗口、最大化、125% 和 150% 缩放，以及浏览器加载失败的情况。

## 5. 创建项目：参考截图的居中表单

参考用户提供的截图：顶部“创建项目”与关闭按钮，中间项目名称和源文件夹区域，底部取消与主操作。沿用这套信息顺序，尺寸、颜色和间距匹配本应用。

```text
创建项目                                       ×

项目名称
[ 自动使用文件夹名称，可修改                    ]

源文件夹
┌─────────────────────────────────────────────┐
│                  文件夹图标                 │
│              点击选择项目文件夹             │
│       将此文件夹作为项目的工作目录           │
└─────────────────────────────────────────────┘

                            取消    创建项目
```

文件夹图标使用现有 SVG 图标组件；示意中的文字不是实际图标。整个源文件夹区域可点击，支持 Tab 聚焦后按 Enter 或空格打开系统文件夹选择器。

### 一次完整操作

1. 点击现有“创建项目”入口，在当前应用窗口内居中打开弹窗，焦点落在项目名称。
2. 用户可先填名称，也可直接点击源文件夹区域；弹出当前窗口所属的系统文件夹选择器。
3. 选择后显示文件夹名称和完整路径，提供“更换”与“移除”。长路径视觉截断，但可查看和复制完整路径。
4. 名称尚未编辑时，自动填入文件夹名称；用户已填写时保留原值。重选目录也不覆盖用户主动输入的名称。
5. 名称与目录有效后，“创建项目”可用；点击后显示“正在创建…”，防止重复提交。
6. 成功后关闭弹窗，选中左侧的新项目并进入其工作区，提示“项目已创建”，用户可立即开始对话。

“创建项目”在本方案中表示将选择的已有文件夹登记为项目；项目显示名称独立于磁盘目录名，修改名称不重命名磁盘目录。用户需要新建磁盘目录时可使用系统选择器的“新建文件夹”，减少主弹窗字段。

### 状态与异常

| 状态 | 处理 |
| --- | --- |
| 未选择目录 | 主按钮不可用，目录区域提示“请选择项目文件夹” |
| 系统选择器取消 | 返回表单并保留已填写信息 |
| 名称只有空白 | 字段下方提示“请输入项目名称” |
| 路径不存在或不可访问 | 显示具体原因，提供重新选择；不创建失效项目 |
| 同一路径已经添加 | 提示“该文件夹已属于项目”，提供“打开已有项目” |
| 同名不同目录 | 以路径区分，提示存在同名项目，允许修改显示名称 |
| 创建失败 | 保留表单、恢复按钮，提供可重试的错误提示 |
| 关闭表单 | `×`、取消和 Esc 行为一致；选择目录本身不创建项目 |

首期一项目对应一个源文件夹。文件夹选择器优先打开最近使用的有效目录，否则采用系统默认位置。避免同一操作连续弹出多个选择器；选择器取消后焦点回到源文件夹区域。

已有代码包含系统目录选择器，可作为复用候选：[electron-app.mjs](../../apps/dsh-desktop/src/electron-app.mjs)。但它当前的调用场景不等于新的创建项目接口已经可用；实施时需核实官方 NPM SDK 的工作区登记能力、重复目录判断及会话关联。通过自有插件和必要的桌面桥接完成，不修改官方源码，也不移除已有打开、导入和远程项目入口。

## 6. 任意文件拖入：统一附件体验，提供真实读取能力

### 当前实现的实际边界

已有内部工作区文件拖动和外部系统文件拖动。小图片沿用原生附件处理，大图片有预处理；小于 1 MB 的部分文本文件读取后直接插入草稿；PDF、Office、压缩包、二进制和大文件主要插入路径引用。取不到路径时可能退化为仅有文件名的链接，非图片处理错误还有被忽略的路径。

代码依据：[拖放入口](../../packages/dsh-aionui-panel/src/client/drag/DragFileInlay.tsx)、[文件处理与引用](../../packages/dsh-aionui-panel/src/client/drag/file-drag.ts)。

### 统一使用方式

用户可以把任何扩展名的文件拖到当前对话区域；靠近输入区时显示轻量提示“松开添加文件”。释放后在输入框上方显示附件卡片，原有草稿不被覆盖，也不直接塞入整篇文件内容。

```text
[方案.pdf  240 KB  已添加  ×] [示例.ts  8 KB  可读取  ×]
[照片.png  缩略图  已就绪 ×] [资料.zip  正在添加…  取消]

[ 输入你的问题，例如：请结合这些文件检查方案。       ]
```

“支持任意文件拖入”指任何类型都能进入统一添加流程，并得到明确结果；模型是否能直接理解内容取决于文件格式、当前工具和模型能力。不能用只有名称的链接冒充有效附件，也不能宣称所有二进制格式都已被解析。

### 文件处理规则

| 类型 | 附件表现 | 发送给模型的内容或能力 |
| --- | --- | --- |
| 图片 | 缩略图，必要时显示压缩状态 | 沿用现有图片附件能力；不支持图片的模型给出切换或处理提示 |
| 文本、代码、Markdown、CSV | 文件图标、名称、大小，可按需预览 | 使用可访问引用或受控文本内容；截断必须可见，不能静默漏掉尾部 |
| PDF、Word、表格、演示文稿 | 对应文件图标和添加状态 | 提供真实文件引用；有读取工具时按需解析，否则明确“已添加，当前无法解析此格式” |
| 音频、视频、压缩包、二进制 | 通用或对应类型图标 | 提供文件引用与工具可用性说明，内容不自动展开或执行 |
| 大文件 | 先展示卡片与大小，再分阶段处理 | 避免一次性读入界面内存；超出当前传输或解析上限时显示实际限制与替代路径 |
| 工作区内文件 | 文件名及所属目录提示 | 使用已验证的工作区引用，不重复复制已有文件 |

外部文件要在当前会话对应的运行环境中真实可读取：本机可用受限的单文件访问能力，或添加到当前会话管理的附件目录。不能仅把本机绝对路径交给远程运行环境。远程会话需经现有上传能力传入对应环境，缺少能力时明确失败，不能显示“已就绪”。

文件能力绑定用户、工作区和会话；实施时核验官方附件接口以及 Electron 文件路径取得方式，不能继续把旧的 `File.path` 当作始终可用的前提。拖入文件只授权处理所选文件，不隐式开放其整个父目录。

### 必须可感知的状态

- 每个文件独立显示“正在添加、已就绪、添加失败、已取消”，失败项提供重试和移除。
- 一批文件部分失败时，保留成功项并指出失败文件；发送前明确哪些附件会发送，允许用户移除失败项后继续。
- 正在添加时防止提前发送导致附件丢失，输入文字仍可继续。新拖入的一批进入队列，保留原始顺序。
- 同一路径重复拖入提示“已添加”；同名但不同目录的文件分别保留，不以名称误判重复。
- 空文件、读取失败、未知 MIME、中文名称和特殊字符都有明确处理，不使整个批次失败。
- 切换会话后，尚在处理的附件不会写入新会话；移除附件不会删除用户的源文件。
- 切换会话再回来保留草稿附件；重启后恢复依赖现有草稿持久化能力，引用失效时标明“请重新添加”。
- 拖入发生在文件树、浏览器网页或项目创建弹窗时，交由对应区域处理；不使用全局监听抢占所有拖放。目录拖入提供“作为项目打开”的引导，避免误读整个文件夹。
- 用户只有点击发送后，才进入模型请求流程。提供“添加文件”选择器作为拖动以外的等价操作入口。

实现优先复用官方会话输入与附件接口。若官方 SDK 没有通用文件附件类型，则通过自有插件展示附件卡片，再使用官方允许的消息或工具能力提交真实引用；不得伪造 SDK 附件字段或修改官方 DSH 源码。

## 7. 统一视觉和层级

继续使用现有主题变量、字体、线性图标与按钮组件。参考截图提供布局，实际颜色跟随当前应用主题；浅色界面不嵌黑色区域，深色界面不出现硬编码白色表单。

| 元素 | 设计约定 |
| --- | --- |
| 新建项目弹窗 | 桌面建议宽约 560 像素，最大不超过当前窗口减去左右各 24 像素；高度自适应，长内容内部滚动 |
| 标题与正文 | 标题建议 20–22 像素、正文 13–14 像素；最终对齐已有组件规格 |
| 按钮 | 主按钮突出，取消为次要操作；高度沿用现有表单，不照搬截图的放大尺寸 |
| 源文件夹区域 | 整块可点击，边框与悬停反馈清晰；选完后收紧为目录信息卡 |
| 附件 | 紧凑排列，过多时换行或限定区域滚动，保留输入框空间 |
| 关闭按钮 | 位置固定、对比清晰，悬停与键盘焦点可见 |
| 层级 | 当前页面、应用弹窗、所属系统文件选择器依次在上；关闭上层后恢复下层焦点 |

初次打开的弹窗均以所属应用窗口可用区域居中。校验 1366 × 768、小窗口和高 DPI；标题、底部按钮及关闭操作始终可达。减少动态效果的系统设置生效时，去掉非必要动画。

## 8. 实施顺序与交付验收

交付检查以实际结果为准：文案核对模式菜单、首次引导和拓展坞三处；浏览器覆盖成功页与错误页；项目覆盖空表单、已选择、重复和创建失败；文件覆盖单个、多选、混合类型、移除、重试及处理期间切换会话；性能单独附上测试环境和测量数据。

本次评审建议确定的默认方案是：中文功能名统一，拓展坞保持既有布局，浏览器提供常驻关闭按钮，项目采用单源目录的居中弹窗，文件采用可移除且状态可见的附件卡片。涉及具体 SDK 接口的可行性检查属于实施的第一步，不将尚未验证的接口当作现成能力。
