This records the baseline investigation and the first candidate gate results in the isolated `codex/desktop-4.2.0` worktree. It does not claim 4.2.0 compatibility or release acceptance.

## Current Desktop dependency and startup path

`apps/dsh-desktop/package.json` pins `@deepseek-ai/dsh` and the directly installed `@deepseek-ai/dsh-*` cohort to `0.1.6-alpha.1`. `pnpm-lock.yaml`, the runtime graph checks and `apps/dsh-desktop/runtime-support/` bind the reviewed graph. The Desktop profile still mounts the patched `@linxin666/dsh-web-ui-all@0.2.5` carrier, selected published `0.3.20` plugins, local workspace forks and Desktop-only bundles. The seven local upstream-family forks inspected so far range from `0.1.15` to `0.1.18`; their upstream `alpha` counterparts are `0.3.23`.

`electron-app.mjs` prepares the Desktop profile and calls `resolveDshCliPath()`; `DshRuntimeController` launches `runtime-launcher.mjs` and waits for a ready signal plus loopback health probing. The profile resolver in `profile.mjs` prefers the old published aggregate, then selected Desktop overrides; `createDesktopProfileManifest()` preserves non-managed community bundle rows. Runtime and repair profiles have distinct names. Main and secondary windows retain `contextIsolation: true`, `sandbox: true` and `nodeIntegration: false`; renderer authority crosses preload, IPC and main-process checks.

The current 4.1 migration is a prepare/healthy-commit/rollback transaction over profile and settings files. Replacing the aggregate needs an additional versioned 4.2 migration that preserves user dependencies, enabled or disabled plugin rows and settings; a package rename alone would leave old profile entries and patch IDs behind. Existing `desktop-v4.1.0` markers must remain valid.

## Upstream artifact mismatch blocking aggregate promotion

The registry tarball of `@linxin666/dsh-web-all@0.3.23` was installed temporarily and compared with the `alpha` commit above. They are materially different despite the same version number: the NPM manifest declares DSH `>=0.1.5-rc.1`, depends on `dsh-better-sidebar@0.19.1`, and its `cordis.patch.yml` SHA-256 is `9A4809E2C6C0FC701C89AAED54B4B88626E11245C3B366669CFC8CC780D059FE`. The inspected `alpha` source declares `>=0.1.6-alpha.2`, excludes that sidebar, and its patch SHA-256 is `76EB3FD8BE6CAADDC822B747311AB06616B766026791929B7255D8C600459901`. The registry's Task Board and Remote Web UI also declare the older engine range. Therefore the published 0.3.23 is not evidence that the inspected alpha branch can be consumed as an alpha.2-compatible NPM aggregate. The temporary dependency was removed from the Desktop manifest and lockfile; do not promote it to the profile.

Safe choices are: upstream publishes a new immutable NPM version from its alpha branch, or Desktop vendors a pinned, reproducibly built upstream source cohort with explicit provenance and tests. The latter is a materially larger distribution choice and would need to replace the current NPM-based aggregate assumption. No equivalent 4.2.0 release claim is possible from the current tarball alone.

A source-cohort feasibility check copied the pinned alpha checkout to an isolated temporary build directory, installed its frozen lockfile, and ran `pnpm --filter '@linxin666/*' -r pack` there. It produced 21 local tarballs totaling 15.7 MB. The rebuilt aggregate tarball declares `>=0.1.6-alpha.2` and all workspace dependencies are converted to exact `0.3.23` specs. The source cohort's full `pnpm typecheck` passes; its aggregate tests report 39 passed and eight existing skips. The upstream checkout remains clean. This proves the source can be packed without publishing NPM, but the tarballs have not been adopted into Desktop's dependency graph or subjected to data migration and plugin smoke tests. The output under the system temporary directory is an experiment, not a release artifact.

The copied source cohort's complete `pnpm test` is red on this Windows host: the Pet package reports two failed symlink-protection tests because creating a symlink returned `EPERM` in the temporary directory, and the run logs a missing published DSH UI primitives source map while loading Git Graph. A diagnostic rerun excluding Pet still had one Doctor rollback/repair concurrency assertion fail, although that 26-test file passed in isolation. This run was not used to relax or skip upstream assertions. A package-level and interactive-platform follow-up is required before treating that source cohort as fully accepted.

## Candidate gate results

`scripts/prepare-dsh-candidate.mjs --version 0.1.6-alpha.2` updated the exact official dependency graph and lockfile. `pnpm install --frozen-lockfile`, `node scripts/runtime-deps-check.mjs` and `node scripts/runtime-graph-check.mjs` pass; the latter checks 98 identity-sensitive packages. Fresh full `pnpm typecheck` now passes after fixing the Task Board, Remote Web UI and model-selection API changes. The typecheck scripts for all 13 composite TypeScript packages now use `tsc -b --force`: tracked incremental cache data had otherwise masked genuine alpha.2 errors.

Desktop-owned AionUI main-view selection, Live Stats active-model selection, Project Dialog navigation and Mode Switcher navigation have been adapted to `retainedBy.mainView` and `uiWorkspace.openSession`. Their focused typechecks and tests pass. The Task Board's Desktop v3 Worktree review and Evidence features are absent from upstream `0.3.23`, so blindly replacing that fork would violate feature preservation. It is a documented Desktop exception: its navigation now uses `uiWorkspace`; background execution retains an exact Session generation through turn settlement and releases it on failure, settlement or board unload. Its 242 focused tests pass, including new ownership tests. The Desktop Remote Web UI deep link now uses `uiWorkspace.openWorkspace`; its mobile compatibility bridge no longer reads the removed Host-wide `queue` control frames. Model Preferences now honors the official `RemoteResult` selection response. The old aggregate remains pinned while the upstream-first replacement and profile migration are implemented; the local changes alone do not make a working 4.2 Desktop.

AionUI's optional panel mount now catches delayed DOM-observer setup/cleanup errors and uses independent React error boundaries for its Explorer and Preview roots. A regression injects an Explorer render failure and verifies that the other panel and the conversation send control remain usable. Its focused typecheck and five lifecycle tests pass. This is a plugin-local failure boundary, not a substitute for a fault-injected packaged Electron smoke test or broader optional-plugin isolation.

The Core Desktop E2E first stopped at the selected-balance scenario. DOM inspection showed the alpha.2 official default is `deepseek-flash` / `DeepSeek-V41-Flash`, while the test still selected the old display name. After updating the fixture to the official alpha.2 model, the scenario exposed a real renderer exception: the retained `dsh-better-sidebar@0.14.0` registered `conversation.chat.turnTail` as an old chain slot without an ID. The Desktop package patch now registers a stable list-slot ID and reads produced paths from the alpha.2 Turn `deliverables` data. Both patched client bundles pass direct contract tests, and the real selected-balance Electron scenario now passes with no renderer page error.

The next Core E2E run reached native navigation and reported the old `[data-composer-stats]` selector missing. An Electron DOM diagnostic confirmed the official alpha.2 stats are separate speed and cumulative-usage buttons; the Desktop `data-dsh-live-stats` supplement still renders with correct input/output, throughput and cost. The test now checks those two official controls and the single Desktop disclosure independently. Its focused native-turns/browser-tabs/mode-switch run passes, including a 20-turn close-and-restore round trip. This was a stale test selector, not a missing Live Stats mount.

The machine baseline structural gate still passes, but built-in adaptation deliberately rejects the candidate because its reviewed manifest records alpha.1. Do not change that manifest solely to silence the gate; it must be regenerated from actual alpha.2 package, mount and runtime evidence.

The alpha.2 runtime launcher no longer imports the removed `watchUserPatches` export. It supplies the official Plugin Manager/HMR `profileContext` before boot and delegates live patch watching to the official runtime. The focused `official DSH host serves the complete desktop profile` integration test passes on this candidate, as does the launcher composition test. This proves startup of the present profile, not the compatibility or completeness of the unresolved upstream aggregate.

The earlier full `pnpm test` reached the Desktop suite: 1,248 passed, five failed and two skipped out of 1,255. Four deterministic failures were fixed and their focused reruns passed: native binding recovery accepts the alpha.2 CLI package's non-root export map, Agent Team's exact version follows alpha.2, and two profile-dump tests materialize the managed runtime package links required by the new official bundle resolver. The Windows console-observer positive control had inherited a hidden console, so it did not exercise the observer. The fixture now explicitly allocates and shows a fresh console for that positive control. Its paired negative and positive tests both pass, and the Core E2E direct-start integration passes all 166 tests. The complete `pnpm test` rerun now passes; the Desktop suite reports 1,255 passed, zero failed and two skipped out of 1,257.

After the sidebar and stats corrections, `pnpm desktop:regression:e2e` passed all 20 Core suites in 532.4 seconds. This includes real Electron startup, plugin pages, Skill Center, model selection, a 20-turn history restore, Browser/Workspace navigation, Runtime stop and recovery, and the Windows Job-child console probes. The Core run is source-backed and does not constitute a packaged installer or three-platform upgrade acceptance. `pnpm build`, forced `pnpm typecheck` and `pnpm install --frozen-lockfile --ignore-scripts` also pass on the current candidate.

The historical direct-start fixture matrix now includes a privacy-safe 4.1.0 Home shape derived from the real `desktop-v4.1.0` tag (`147d37edd7eecce2101e632f1d0d0a04d6a6ddd7`). Provenance hashes cover the fixture, and a regression rejects silently dropping its enabled Skill Center bundle. The focused 10-test matrix and session-preservation suite pass. This is a release-profile compatibility fixture, not a real 4.1 installer overlay or full user-data migration.

`pnpm feature-baseline:check` passes its structural inventory (19 plugins, 13 builtins, 32 surfaces, 15 skins) but correctly rejects the alpha.1 reviewed adaptation manifest against the alpha.2 candidate. Preserve that failure until the final aggregate and mounted runtime graph have been reviewed.

No 4.1-to-4.2 profile transaction, plugin state migration, smoke matrix, three-platform package, or user-data round trip has been verified. The clean 4.1 baseline checks above cannot be used as evidence for 4.2 completion.
