# 官网累计安装包下载量设计

## 目标

官网首屏展示所有现存 Windows x64 安装包的累计下载次数，而不是只展示最新版本资产的下载次数。页面布局、下载链接和最新版本信息保持不变。

## 方案

浏览器空闲时请求 GitHub Releases 列表，遍历每个 Release 的资产，只汇总名称符合 `DeepSeek-Harness-Desktop-Setup-*-x64.exe` 的 `download_count`。当前仓库 Release 数量低于 GitHub 单页上限，因此请求 `per_page=100` 即可覆盖全部现存安装包。手工维护累计值会快速过期，新增后端或定时生成文件会增加不必要的部署复杂度，因此不采用。

## 兜底与性能

HTML 内保留发布时确认的累计数字，网络失败、GitHub 限流或返回异常数据时继续显示该兜底值。最新 Release 请求仍负责下载链接、版本、大小和发布日期；累计统计请求独立失败，不阻塞页面渲染，也不改变下载按钮行为。

## 验证

将资产筛选与求和提取为可测试函数，覆盖有效安装包、校验文件、其他平台资产和无效计数。官网校验继续要求累计下载标记存在，并通过本地浏览器确认页面文字显示“累计安装包下载”。
