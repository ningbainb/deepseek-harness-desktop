# DeepSeek Harness Desktop 3.0.0 Stability Release Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Deliver an additive 3.0.0 stability release with explicit compatibility guarantees, recoverable upgrades, privacy-safe diagnostics, and trustworthy stable/beta packaging.

**Architecture:** Keep the existing Electron shell, DSH Runtime Provider, Desktop Contract, Task Board, and PluginManager intact. Add versioned validation and policy modules at the Desktop boundary; use the existing atomic profile and recovery primitives for migration; keep diagnostics redacted before archiving; and make release channel/signing checks fail closed only for configured official Stable releases.

**Tech Stack:** Node.js ESM, Electron, electron-builder, GitHub Actions, JSON Schema, fflate, pnpm, Node test runner, Vitest.

---

### Task 1: Freeze and verify public compatibility artifacts

**Files:**
- Create: `docs/schemas/desktop-contract-v1.schema.json`, `docs/schemas/runtime-provider-v1.schema.json`, `docs/schemas/supported-runtime-matrix-v1.schema.json`, `docs/schemas/compat-patch-registry-v1.schema.json`, and task/evidence schemas.
- Modify: `apps/dsh-desktop/src/desktop-contract.mjs`, `apps/dsh-desktop/src/runtime-provider.mjs`, runtime-matrix generators, and compat-patch registry validation.
- Test: Desktop Contract/Provider tests, patch-registry tests, schema validation tests, and legacy compatibility fixtures.

1. Add machine-readable schemas and a deterministic validator.
2. Make Stable runtime status derive from a matching matrix entry and reject non-Stable statuses.
3. Require patch ownership, applicability, tests, removal condition, and verification freshness.
4. Preserve v1 readers for valid old data, ignore unknown optional fields, and give actionable errors for unknown required majors.

### Task 2: Add migration and recovery orchestration

**Files:**
- Create: `apps/dsh-desktop/src/migration-assistant.mjs`, representative migration fixtures, and migration-matrix tests.
- Modify: recovery/startup integration only as needed to expose the standalone recovery surface.
- Test: 2.3 through 2.7 plan, snapshot, journal, rollback, and resume scenarios.

1. Scan profile, state, support evidence, managed patches, and compatibility records without DSH Web.
2. Create private atomic snapshots excluding project content and secret values.
3. Persist journal states and resume/rollback safely after interruption.
4. Bound rollback retention and expose conservative guidance for unknown older installations.

### Task 3: Create privacy-safe diagnostic archives

**Files:**
- Modify: `apps/dsh-desktop/src/startup-diagnostics.mjs`, `src/extension-ipc.mjs`, IPC/startup integration, and tests.
- Test: secret, private-key, prompt, session-history, tool-result, path, and URL-credential regression corpus.

1. Centralize redaction before any JSON or ZIP serialization.
2. Offer a content manifest and explicit user confirmation before writing a user-selected destination.
3. Include only bounded diagnostic facts, hashes, and counts; never user content or credentials.

### Task 4: Harden channels, signing, and release artifacts

**Files:**
- Create: release-channel and release-manifest modules/tests.
- Modify: updater, electron-builder configuration, desktop release workflow, package scripts, release templates, and package verification.
- Test: Stable/Beta isolation, higher-beta no-auto-downgrade, unsigned build, required-signing failure, manifest/hash validation, and signer verification seams.

1. Persist `stable|beta`, default existing users to Stable, and keep update feeds/channels separate.
2. Allow unsigned local/community packages, but fail a configured Stable release with missing signing credentials.
3. Produce SHA-256 and a release manifest that records channel, artifact, signature, schemas, provider, and matrix evidence.

### Task 5: Finish policy, documentation, and release gates

**Files:**
- Create: compatibility, schema-versioning, runtime-support, upgrade/rollback, diagnostics-privacy, and security-boundary documents plus minimal SDK/Preset examples.
- Modify: README files, `docs/desktop.md`, CHANGELOG, release notes, CI/release workflows, telemetry configuration, and version metadata.
- Test: `pnpm verify`, targeted Desktop tests, migration matrix, packaging verification, and all locally executable release checks.

1. Disable default telemetry/upload and reconcile obsolete 2.7 policy wording.
2. Bump Desktop to 3.0.0 while retaining SDK/Contract v1 compatibility.
3. Gate Stable releases on allowed runtime matrix states and required release evidence.
4. Report Windows/certificate-only checks separately when not runnable locally.

No commit, push, or pull request is part of this plan.
