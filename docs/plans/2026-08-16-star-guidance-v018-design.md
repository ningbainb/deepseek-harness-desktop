# 官网 Star 引导与 v0.1.8 内容设计

## 目标

在不重做现有官网视觉和信息架构的前提下，提高访客发现 GitHub Star 入口的概率，并让官网与仓库首页准确表达桌面版 v0.1.8 的能力。

## 设计方向

保留当前深海黑色主视觉、动感亮色主题、Hero 双栏结构、现有按钮样式和滚动揭示动画。参考 dshdesktop.cn 的社会证明思路，在顶部导航加入带实时数量的 Star 胶囊，把 Hero 的普通 GitHub 按钮改成明确的“去 GitHub 点 Star”，并在主按钮组下加入一行克制的支持说明。下载始终保持第一主操作，不增加弹窗、不拦截下载，也不使用虚构数字。

Star 数量通过 GitHub 仓库公开 API 在页面空闲时异步获取，HTML 保留当前真实数量作为降级值。最新 Release 接口已经返回安装包下载次数，复用这份响应展示下载社会证明，不增加额外 Release 请求。接口超时或限流时，页面继续使用静态降级信息，不影响下载和导航。

## 内容结构

在现有基础能力与详细特色之间加入“v0.1.8 新增”区块，使用与当前卡片一致的边框、圆角、字体和动效，展示 ChatGPT OAuth 与 OpenAI Codex、推理强度滑块、帮助菜单中的社群和建议入口、单一插件市场与安全迁移四组能力。同步将主题数量更新为实际的 11 款，并让 Release 卡片直接概括 v0.1.8 的关键变化。

根 README 中文与英文同步更新稳定版、下载链接、版本表和内置市场描述，避免官网与 GitHub 项目介绍互相矛盾。

## 验证

扩展官网校验脚本，要求 Star 入口、实时数量占位和 v0.1.8 功能区存在。运行网站单元测试、官网资源校验、文档校验和差异格式检查；启动本地静态服务器，在桌面与 390 像素移动视口检查首屏、功能区和 Release 区域，确认没有横向溢出且下载仍是最突出操作。
