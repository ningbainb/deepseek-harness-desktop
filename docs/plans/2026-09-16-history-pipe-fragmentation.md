# Desktop 4.0 大历史与上下文输送修复

## 问题

Desktop 4.0 的 Runtime Pipe 将每个流值编码为单个 JSON 帧，单帧上限为 512 KiB。历史接口的初始 snapshot 可同时包含 records 和 projections，超过上限时会在进入渲染器前被传输层拒绝，页面只看到 `runtime carrier Error`。

## 修复约束

- 不修改官方 DSH 源码或用户会话 JSONL。
- 保留 512 KiB 物理帧上限，不通过无界调大阈值规避问题。
- 对超限的逻辑消息分片，逐帧等待背压，接收端按 ID、序号、片数和总字节数校验后重组。
- 单条逻辑消息仍限制为 320 MiB；超限、乱序、缺片、非法 Base64 和 JSON 均必须失败关闭。
- 传输错误只记录字节数、上限和稳定错误码，不记录历史正文、路径或凭据。

## 验收

1. 小帧保持原协议行为。
2. 超过 512 KiB 的中文历史 snapshot 完整返回并可取消。
3. 超过 512 KiB 的 duplex 输入和输出完整往返。
4. 组装中断不产生部分对象，而是显式失败。
5. 功能基线、Desktop 单测、会话重开 E2E 和打包回归通过。
