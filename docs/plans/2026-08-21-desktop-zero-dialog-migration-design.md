# Desktop 零选择迁移与自由模式兜底设计

## 目标

Desktop 3.0 启动时不再要求普通用户理解迁移日志、快照或回滚状态。检测到 2.3–2.7 状态后，Desktop 自动创建私有快照、确认受支持的迁移计划并继续全部待执行步骤。成功后直接显示主界面，不显示“继续迁移”“回滚并退出”或“迁移完成”弹窗。

Desktop 的主界面继续由 Electron 内嵌的 loopback DSH Runtime 提供。该 HTTP Runtime 是 Desktop 渲染层，不是额外启动的 Web 产品；启动和迁移代码不得把 loopback URL 交给系统浏览器。迁移旧浏览器任务账本时允许创建受限的隐藏 Electron 探针，探针完成后立即销毁。

## 状态流

1. 启动前扫描既有迁移日志；不存在时生成迁移计划。
2. 对 2.3–2.7 的 `safe` 和 `needs-confirmation` 计划统一创建私有快照与日志。
3. 自动确认尚未确认的日志，并幂等执行剩余步骤。
4. 迁移提交后继续正常 Desktop 启动。
5. 扫描阻断、日志不可读或迁移执行失败时，不退出、不循环重试，也不显示迁移选择页；立即尝试启动内置自由模式。
6. 自由模式首次启用时请求一次全权限确认并记住 Desktop 工作台来源；之后再次触发兜底时直接进入，不重复弹窗。只有自由模式也失败、首次确认被取消或长期授权已被撤销时，才保留本地恢复页和日志入口。

## 交互

删除启动页的“升级与迁移”按钮。保留工具菜单中的维护入口，但入口只触发同一套自动迁移，不显示确认、回滚成功或迁移完成对话框。技术用户仍可从私有快照和诊断日志实施恢复，普通用户不需要在启动阶段做决定。

恢复界面保留“撤销自由模式和外来插件长期授权”入口。撤销后下一次启用自由模式会重新请求确认；权限账本损坏时不复用旧授权，只允许一次性会话。

## 验证

- 单元测试覆盖 `safe` 与 `needs-confirmation` 都自动继续，未知/损坏日志不被误判为可迁移。
- 源码集成测试证明迁移启动路径不再创建选择型 Recovery Shell，也不会在失败后无限循环。
- 打包迁移矩阵中的 2.3–2.7 全部改为无人值守自动路径。
- 打包冒烟验证 Runtime、Renderer、任务账本和 Git 工作流仍能进入可用状态。
