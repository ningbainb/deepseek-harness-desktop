# Desktop 3.0.8 Local Release and Main Merge Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Prepare the repaired Desktop build as local release version 3.0.8, update the public website and release documentation, verify the release gates, build local unsigned artifacts, and fast-forward the local `main` branch without pushing or publishing externally.

**Architecture:** Treat 3.0.8 as the next patch release over the current 3.0.7 checkout. Keep the pinned DSH 0.1.1-rc.1 runtime and the existing direct-start/automatic-repair behavior unchanged except for release metadata and public claims. Use the repository's generated runtime-support metadata and website validators as release sources of truth.

**Tech Stack:** pnpm, Node.js, Electron, electron-builder, static website validators, Git.

---

### Task 1: Confirm release scope and version sources

- Verify the current branch, worktree, package versions, runtime lock, and release scripts.
- Preserve unrelated user files, including stale local image assets that are not part of the 3.0.8 release.
- Update the plan if the repository reveals a generated source that must be changed first.

### Task 2: Prepare version 3.0.8 metadata and public claims

- Bump the root and Desktop package versions to 3.0.8.
- Regenerate or update runtime-support metadata and lockfile references required by the repository.
- Add bilingual 3.0.8 changelog and release notes covering direct startup, visible repair progress, safe diagnostics, and tools capability handling.
- Update the website fallback content, download links, release metadata, and current-release documentation to 3.0.8.
- Keep historical 3.0.7 references where they describe history rather than the current release.

### Task 3: Run release verification

- Run `pnpm verify` and fix only release-scope failures.
- Run the Desktop package checks and focused repair/runtime tests.
- Run the unsigned directory packaging flow and validate the generated manifest/artifacts.
- Run packaged smoke/direct-start checks that are available locally; record any Windows-only checks that cannot run as `NOT RUN` rather than claiming success.

### Task 4: Commit and merge locally

- Review the final diff and ensure stale QR/poster files are not staged accidentally.
- Commit the implementation/release changes with a non-emoji message.
- Fast-forward local `main` to the release commit.
- Recheck the merged branch, version, worktree, and local build artifact paths. Do not push or create tags/releases.
