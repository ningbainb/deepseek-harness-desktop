# Desktop 凭据兼容、匿名分析与拓展坞增长设计

**状态：** 已确认，进入实施。

**日期：** 2026-08-22。

**适用版本：** Desktop 3.0.2 及后续 3.x。

## 一、结论

Desktop 启动时继续直接读取当前 `DSH_HOME`，不恢复迁移壳、隔离会话或用户选择按钮。

如果当前运行环境缺少模型 API Key，Desktop 只从本产品拥有的旧隔离目录中兼容读取旧凭据，并把缺失项注入本次 Runtime；当前环境和当前凭据始终优先，旧文件不移动、不删除、不覆盖，秘密值不进入日志和埋点。

官方 Desktop 包恢复默认匿名产品分析，以 Desktop 独立生成的本地随机秘密派生每日和每月匿名标识，统计 DAU、MAU、国家级用户数、版本采用、应用内更新漏斗和拓展坞漏斗；开发版、源码运行和第三方构建默认关闭。

拓展坞入口放在左下角设置旁边，一次点击打开；前 3 次符合条件的启动显示轻量提示“插件、技能和桌面核心功能在这里”，用户点击、关闭或达到 3 次后停止展示。

正式 Windows 产物使用现有 NSIS 流程生成无签名安装包，系统可显示“未知发布者”；签名不是本次发布门禁。

## 二、产品边界

1. 新用户只初始化最新版内置 Profile、内置插件、插件市场和应用状态，不执行迁移扫描。
2. 已有用户直接使用原 Home、原会话、原 Profile、原插件和原设置，兼容读取在各数据存储内部完成。
3. 凭据恢复只补齐缺失值，不改变用户已经生效的 Key，不恢复任意外部目录，不读取会话正文。
4. 产品分析只用于产品使用和更新效果统计，不发送提示词、消息、文件名、插件名、密钥、完整路径、IP 或设备硬件标识。
5. 地区维度只保留国家或地区代码，由服务端从请求上下文得到，客户端不申请定位权限。
6. 拓展坞提示不使用模态框，不阻塞输入，不要求用户理解插件架构。
7. 无签名正式包允许出现 Windows SmartScreen 或未知发布者提示，版本、文件名、更新清单和校验和仍必须完整。

## 三、旧 API Key 兼容读取

### 事实源和优先级

当前凭据事实源仍是当前 `DSH_HOME/.credentials.yaml` 和进程环境变量。

解析优先级从高到低为：当前进程环境变量、当前凭据服务已经解析的 `refs`、产品拥有的旧隔离目录中最新的有效 `.credentials.yaml`；旧值只填充空缺，不覆盖任何高优先级值。

兼容扫描范围限定为 Electron `userData/free-mode-sessions/active/*/dsh/.credentials.yaml` 及产品已经记录的旧 Free Mode 会话目录，不递归扫描用户磁盘，也不读取其他应用凭据。

兼容读取支持当前 `version: 1` 的 `refs` 映射和历史平铺键值格式，只接受合法的环境变量式引用名和字符串值；`records` 中的 OAuth 或 Provider 私有结构本轮不转换为环境变量，避免错误扩权。

### 运行时行为

Desktop 在生成 DSH 子进程环境前完成只读兼容解析，把恢复到的引用合并到子进程环境；Models 页面和模型调用因此能把它们视为环境凭据。

读取失败、文件损坏或没有旧值时，Desktop 正常继续启动，不弹迁移页面；诊断只记录候选数、恢复引用数量和错误类别，不记录引用值。

兼容层不写回 `.credentials.yaml`。用户下一次在当前设置页保存 Key 时，由当前凭据服务按最新版格式写入。

### 回归门禁

测试必须覆盖当前值优先、只补缺失项、多个旧目录选择最新有效值、损坏 YAML 跳过、非法引用名拒绝、旧文件字节不变和日志不包含假秘密。

历史 Home 启动矩阵增加带旧 `.credentials.yaml` 的 3.0 Free Mode 样本，并在打包应用中验证模型环境可见但控制台和诊断文件不可见。

## 四、匿名活跃与地区统计

### 本地身份

Electron `userData` 新增独立的产品分析状态文件，首次官方包启动时生成高熵随机秘密。

客户端不发送该秘密或长期稳定安装 ID，而是分别派生：

- `dailyActor = HMAC(secret, "day:" + UTC 日期)`；
- `monthlyActor = HMAC(secret, "month:" + UTC 月份)`。

同一安装在同一天或同一月内可去重，不同日期和月份之间不能直接串联；该身份与 DSH `.anonymous-user-id`、账号、会话和 API Key 完全分离。

卸载清除应用数据或用户主动删除状态后会形成新匿名用户，这是隐私优先的预期行为。

### 启用规则

官方发布工作流在打包前从仓库变量注入分析端点，资源同时携带官方构建标记；只有打包资源有效且不是开发模式时客户端发送事件。

本地开发、测试、源码运行、端点为空、第三方重打包和显式禁用都不发送。发布仓库不提交生产端点或秘密。

发送失败不影响启动、更新和 UI，事件队列有大小和超时上限，不无限重试。

### 事件模型

所有事件使用固定词表和低基数维度。

| 目标 | 事件 | 允许维度 |
| --- | --- | --- |
| 活跃 | `app_launch` | Desktop 版本、平台、渠道 |
| 更新 | `update_available`、`update_downloaded`、`update_install_requested`、`update_completed`、`update_error` | 来源版本、目标版本、结果类别 |
| 拓展坞 | `dock_entry_impression`、`dock_nudge_shown`、`dock_nudge_dismissed`、`dock_entry_click`、`dock_opened` | 入口位置、是否提示、结果类别 |
| 拓展功能 | 既有 `extension_operation` | 固定操作类别、固定结果类别 |
| 关键页面 | 既有 `surface_opened` | 固定 surface 名称 |

`app_launch` 携带每日和每月匿名标识；需要唯一用户漏斗的更新与拓展坞事件也携带同周期匿名标识。自由文本、错误原文、插件包名和路径不能进入事件。

### 应用内更新人数

更新器在下载或请求安装时写入最小本地回执，内容只有来源版本、目标版本、阶段和时间。

下一次启动如果当前版本与回执目标版本一致，发送一次 `update_completed` 并消费回执；直接覆盖安装、手动安装或重复启动不伪装成应用内更新完成。

后台同时展示事件次数和按周期匿名标识去重的人数，以区分重复检查与实际用户覆盖。

### 服务端和保留期

Worker 接收事件后从 Cloudflare 请求元数据读取国家或地区代码，不持久化 IP；无有效国家代码时记为 `ZZ`。

D1 保存日活去重行、月活去重行、低基数事件聚合和漏斗去重行。每日匿名行保留 35 天，每月匿名行保留 13 个月，趋势聚合保留 400 天；定时清理只删除超过保留期的数据。

管理面板恢复并新增：DAU、MAU、国家级用户数、版本采用、应用内更新漏斗、拓展坞曝光到打开再到操作的漏斗。面板不提供单个匿名用户的行为时间线。

## 五、拓展坞一键入口

### 位置和交互

内置设置包在 `sidebar.footer.action` 槽注册 Desktop 专用拓展坞入口，使其与左下角设置相邻。

点击入口直接调用 Desktop Contract 打开 `extensions` surface，不经过菜单和二次确认；原“工具”菜单和快捷键继续作为备用入口。

普通 Web、能力不可用或非 Desktop 宿主不显示该入口。Desktop Contract 为主界面新增窄权限 `extensions.open`，不把安装、删除或更新插件的管理权限交给普通渲染器。

### 前 3 次启动提示

Electron 主进程在产品分析状态之外保存独立的拓展坞引导状态，包括符合条件的启动次数、是否点击和是否永久关闭。

首次、第二次和第三次主界面可交互后，在入口旁显示非模态 callout：“插件、技能和桌面核心功能在这里”。用户点击入口、点击关闭、按 Escape 或达到第三次展示后不再出现。

提示不抢焦点、不遮挡设置按钮，支持键盘聚焦、可访问名称、深浅主题和缩放；入口打开失败时给出短暂的本地错误提示，不能静默无反应。

### 成功指标

主要指标是拓展坞入口唯一点击率、唯一打开率和打开后扩展操作转化率；辅助指标是提示曝光到点击转化、设置入口点击率变化和打开失败率。

评估至少按 Desktop 版本和国家级地区分组，不建立个人画像；上线前冻结旧“工具菜单”基线，上线后比较 7 日与 28 日窗口。

## 六、正式打包

Windows 正式产物继续使用 `electron-builder` 的 NSIS target，命名为 `DeepSeek-Harness-Desktop-Setup-<version>-<arch>.exe`。

当签名环境变量不存在时，发布门禁以 `REQUIRE_SIGNING=false` 运行并明确生成 unsigned release manifest；安装包在 Windows 中显示“未知发布者”属于已接受结果。

正式候选必须通过单元测试、历史 Home 和凭据矩阵、打包直启、更新回执、拓展坞 E2E、隐私字段扫描、安装 smoke、SHA-256 校验和与 release manifest 验证。

本轮只在本地生成候选安装包和校验文件，不自动创建标签、推送、上传 GitHub Release、部署 Worker 或修改远程仓库变量。

## 七、故障与降级

凭据兼容失败只意味着缺失 Key 仍由设置页正常提示，不阻塞主界面。

分析端点不可达时丢弃或有限排队事件，不影响用户动作；数据库写入失败返回可重试状态，但客户端不高频重放。

拓展坞入口调用失败保留现有菜单和快捷键，并显示短错误提示；提示状态损坏时回到不展示提示的保守默认，不进入启动恢复。

无签名安装包被系统拦截时，产品文档说明发布者状态和 SHA-256 校验方式；不通过降低 Windows 系统安全设置来绕过。

## 八、验收标准

1. 新用户第一次启动不出现迁移、隔离或恢复选择，直接进入最新版界面。
2. 只有旧 Free Mode 凭据、没有当前 Key 的历史用户可以继续调用相同 API Provider。
3. 当前 Key 和环境变量永远不会被旧值覆盖，旧凭据文件不会被改写或删除。
4. 任何测试日志、遥测事件、诊断导出和 release manifest 都不包含假秘密值。
5. 官方包能统计 DAU、MAU、国家级用户数和应用内更新人数，开发版与第三方构建默认不发送。
6. 服务端不持久化 IP，不接收长期稳定安装 ID，不采集会话、提示词、文件或插件名。
7. 设置旁的拓展坞入口一次点击打开，普通 Web 不显示。
8. 轻提示最多在前 3 次符合条件的启动出现，点击、关闭或按 Escape 后不再出现。
9. 管理面板能查看活跃、地区、版本、更新和拓展坞漏斗，不能下钻到个人行为轨迹。
10. 无签名 NSIS 安装包、校验和和 unsigned release manifest 全部通过本地验证。

## 九、明确不做

本轮不恢复 OAuth `records` 的跨格式转换，不用 MAC、硬盘序列号、账号或 DSH 匿名 ID 做统计，不采集省市级精确位置，不把分析失败变成启动失败，不增加迁移按钮或拓展坞二级入口，不自动部署生产 Worker、发布 Release 或绕过 Windows SmartScreen。
