# 3.3.0 个性化能力 SDK 契约

本文记录 3.3.0 个性化能力依赖的公开 SDK 接缝。契约测试位于 `apps/dsh-desktop/test/sdk-contracts.test.mjs`，依赖通过 Node package resolution 定位，不依赖 pnpm store 的固定路径。本轮范围不包含自定义 `/model` 命令替换，也不把真实手机/LAN A/B 作为完成条件。

## 已验证版本

当前工作树解析到的 `@deepseek-ai/dsh-system-prompt`、`@deepseek-ai/dsh-agent`、`@deepseek-ai/dsh-atomic-write`、`@deepseek-ai/dsh-client-ui-model-selection`、`@deepseek-ai/dsh-client-ui-commands` 和 `@deepseek-ai/dsh-client-ui-slots` 均为 `0.1.0-rc.6`。

## System Prompt

公开类型提供 `SystemPrompt.section({ name, order, text })`、`SystemPrompt.variable(name, provider)` 和 `SystemPrompt.assemble(context)`。section 的 `text` 可以是每次 assembly 执行的同步函数，variable provider 也在每次 assembly 执行，并且最终 section 文本通过 `{{variable}}` 插值。

3.3.0 的 Personal Prompt 和 Memory 采用 `section + variable`：section 负责稳定的数据边界和排序，variable 负责按当前 assembly 解析内容。虽然当前 SDK 也公开 `SystemPrompt.context`，本版本不依赖它作为新功能的唯一接缝，以便沿用仓库中已经存在的 section 接入模式。

`AssembleContext` 当前公开字段只有可选的 `scope` 和 `signal`，没有 owner、workspace 或 session 字段。需要 session 身份的插件必须从公开的 agent scope/lifecycle 接缝取得 agent/session，再通过自有的异步请求上下文和 ownership registry 解析 owner，不能假设 assembly context 已携带用户身份。

## Agent 生命周期

`@deepseek-ai/dsh-agent` 公开 `Agent`，其 `id` 与 `session` 是同一 session 身份；公开事件包括 `agent/created`、`agent/disposed`、`agent/session-start`、`agent/pre-step`、`agent/request` 和 `agent/turn-stopping`。Personal Prompt 和 Memory 可以在 assembly 或 agent scope 中读取当前 session；Memory 的自动写入仍必须经过用户确认，不因存在 `turn-stopping` 就静默保存。

`agent/request` 只能替换 frozen call configuration，不能通过该 waterfall 修改 model-visible messages。个人内容使用 System Prompt 注册表，不能把 request waterfall 当作绕过官方 Prompt 组装的入口。

## Model Selection

`@deepseek-ai/dsh-client-ui-model-selection` 公开 `ModelDirectoryState`、`ModelDirectoryResolver`、`ctx.modelDirectories.directoryFor(sessionId)` 和 `ModelSelectInjected`。`ModelDirectoryState` 同时包含 `current`、`routable`、`groups`、`failures`、`status` 和 `error`，新选择器必须完整保留这些状态语义。

官方模型座位是 `conversation.input.model`，官方实现通过 `ctx.slots.inject` 注册，并让输入框与 `/model` 共用同一 session directory。`@deepseek-ai/dsh-client-ui-slots` 的公开注册类型支持 `priority?: number`；非 chain slot 按升序选择，低 priority 胜出，同一 cell 和同一 priority 重复注册会抛错。因此模型偏好插件可以在通过集成测试证明官方座位存在后，以 `priority: -10` shadow 官方 seat，但不得复制官方目录加载、失败恢复、reasoning effort 或 session availability 逻辑。

## Command UI（本轮不纳入自定义 `/model`）

`@deepseek-ai/dsh-client-ui-commands` 公开 `CommandUiContract.decorate(CommandDecoration)`，但本轮不启用自定义 `/model` 替换。模型偏好插件不注册、不改写官方命令；模型设置页和 composer selector 只复用官方目录的本地投影。

## 原子存储

`@deepseek-ai/dsh-atomic-write` 公开 `writeFileAtomic(filename, content, { mode, dirMode })` 和 `withFileLock(filename, operation, { waitMs })`。自有 user-scope、memory 和其他长期 JSON 存储优先复用这两个接口：目录使用 `0o700`，文件使用 `0o600`，写入先在同目录生成独占临时文件，再 rename；读改写流程用 `withFileLock` 串行化。该 SDK 明确不承诺 fsync，因此 packaged smoke 只要求原子完整性，不把 fsync 当作已提供能力。

## 用户隔离可用接缝

现有 `dsh-remote-web-ui` 已公开配对 cookie、设备 revoke、`/m/api` allowlist、`api/gate` 和 `ApiProxy` 路由边界。公开 `WorkspaceRegistry`/`Workspace` 和 `SessionStore` lifecycle 可以作为资源事实源；当前 `SessionHeader` 没有 owner 字段，因此 ownership 由 `dsh-user-scope` 统一在官方 session 生命周期和受检的远程创建成功后登记，不由 memory 或 Prompt 消费者重复维护。

请求主体不能放在全局可变变量中。若当前公开 SDK 没有 host request scope，`dsh-user-scope` 使用 Node `AsyncLocalStorage<AccessScope>` 包住每个 remote dispatch 和显式本地操作；未知 ownership 一律拒绝远程访问。非 loopback 的完整 `/api` 在 3.3.0 默认拒绝，只保留逐方法过滤的 `/m/api`，避免有未过滤的官方路由绕过设备隔离。真实手机/LAN A/B 不属于本轮验收门槛。

## Contract Spike 的停止条件

如果未来 SDK 升级后缺少上述公开类型或行为，且只能通过官方源码 import、private path 或 runtime monkey patch 继续，则相关功能停止实现并报告，不通过删安全断言或静默降级到未授权路径来保持构建绿色。
